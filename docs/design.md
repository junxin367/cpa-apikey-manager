# 设计与实现

更新日期：2026-10-09。

## 功能边界

插件只读同步 CLIProxyAPI 已有客户端密钥，每把密钥独立开关总额度，并在按渠道／按模型两种配置方式中二选一。总额度与当前模式的分项额度分别选择 Token 或 USD 上限，共同生效，任一耗尽即拦截。每把密钥独立选择日、周、月中的一个周期，所有额度共用。自然周期按“结算时区”计算：即 SQLite `meta.accounting_timezone` 中保存的 IANA 时区；尚未保存时使用宿主服务器系统时区，旧版本可能残留的 `meta.timezone` 始终忽略。管理页打开“设置”时，若服务端尚未保存时区，会自动识别浏览器所在电脑的时区并保存一次；已保存后不再自动覆盖，只能手动选择或点击“使用浏览器时区”。切换时区后按新边界重新汇总已有记录，不删除历史用量。

管理页面“设置”中的请求拦截开关是拦截与记账的总开关，默认关闭并保存在 SQLite `meta`。关闭时请求拦截、完成事件和用量事件全部旁路，配置或密钥来源异常不能影响模型请求；管理接口仍可用于检查配置。明确开启后，插件只处理“`caller_scope` 匹配到宿主密钥且该密钥有生效配置”的请求；未携带 `caller_scope`、无法匹配或没有生效配置的请求直接放行。对已处理的密钥采用失败关闭策略，配置、密钥来源或记账异常会阻止请求。宿主配置读取失败时沿用上次同步的密钥列表识别调用方：有生效配置的密钥返回 503，无配置密钥放行；携带了 `caller_scope` 却无法匹配时无法排除是受限密钥，也返回 503。

总开关开启后，插件先按密钥判断是否存在生效配置：已开启总额度，或当前模式至少有一条渠道／模型规则。两者都不存在时直接放行，不检查模型权限、额度或记账健康状态，也不创建请求与用量记录。存在生效配置时，所有获准生成请求持续记账；未配置范围默认放行，只有当前模式的禁止规则生效。密钥总额度开关关闭保留上限与用量，模式切换保留两套配置；暂停模式中的规则不触发处理。重新启用后按已有账本汇总，旁路期间的消耗不补造。0 额度与不限额分开表示。

渠道固定为 GPT、Claude、DeepSeek、GLM、Kimi、Antigravity、其他。除 Antigravity 外都按实际模型家族划分，与上游供应商无关。Antigravity 是唯一按上游划分的渠道：宿主选中凭据后的拦截（`request.intercept_after`）中 `ToFormat` 为 `antigravity` 时，该次执行归入 Antigravity，不论实际模型是 Gemini、Claude 还是其他；选中凭据前无法得知上游，渠道规则只在选中凭据后检查。模型价格表中的渠道列仍按模型名显示家族。后端集中分类并返回页面，准入时将渠道快照写入请求，结算沿用该快照。已知单目标别名归属目标；多目标别名在实际模型选择后判断，不从别名字符串猜渠道。纯 Token 计数对所有已知候选检查权限，不检查生成额度。

独立管理页包含 API 密钥、模型价格和凭据设置三个入口。没有默认模型权限开关或用量明细页。内部账本继续支持额度汇总和异常核对。

## 原生接入

- Rust `cdylib`，插件 ID `cpa-apikey-manager`；页面嵌入动态库。
- 接入基线为 CLIProxyAPI v8.0.4，提交 `d33f63f8e3d98428440ebca5a5b6a981a61ff71e`，C ABI v1 / RPC schema 6。
- 页面资源不设置 `frame-ancestors`，兼容宿主管理前端通过同源或跨来源 API 地址 iframe 内嵌。
- `cpa-config-path` 可省略：优先识别宿主进程的 `-config/--config` 参数，未指定时使用宿主工作目录下的 `config.yaml`；外部配置存储等无法从进程参数确定路径的部署继续使用显式配置。
- 插件注册始终保留管理资源；运行回调仅在数据库开关启用时进入权限、额度与记账引擎。数据库尚无开关值时初始化为关闭，之后只由管理页面修改；插件尚未完成注册时按关闭处理并直接旁路。
- 使用请求前、凭据选择后、请求完成和用量回调；业务拒绝通过显式终止响应返回，不能以普通插件异常代替。
- 身份来自宿主已认证的 `caller_scope`。密钥明文只在内存中，SQLite 保存 HMAC 标识和脱敏显示值。
- v8 `access.api-keys` 优先，兼容旧根级字符串列表；源文件失败与有效空列表区分。
- 管理接口复用宿主管理鉴权。页面资源可公开访问，不包含密钥或账本数据；完整客户端密钥仅在管理员主动查看或复制单把密钥时通过禁止缓存的管理响应返回。
- 页面同源内嵌时读取官方管理中心 `cli-proxy-auth` 或旧 `managementKey` 浏览器存储，并兼容其 `enc::v1::` 可逆混淆格式。仅当宿主管理中心保存了管理密钥时才能自动复用。
- 跨来源内嵌或宿主未保存凭据时，设置页允许仅本次使用或保存到插件页面所在来源的浏览器存储。插件配置和 SQLite 均不保存宿主管理密钥；设置页可清除插件自行保存的值。

管理路由前缀为 `/v0/management/plugins/cpa-apikey-manager`：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/state` | 脱敏密钥、策略、总用量 `total_usage`、渠道 `channel_usage`、单模型 `quotas`、记账起点及价格 |
| POST | `/key` | 按 HMAC 标识读取一把当前有效密钥的明文，用于管理员主动查看或复制 |
| POST | `/key-search` | 按完整密钥内容搜索当前有效密钥，只返回匹配的 HMAC 标识 |
| PUT | `/settings` | 保存全局请求拦截与记账开关 `enforcement_enabled` 和／或结算时区 `timezone`（IANA 名称），两个字段均可选但至少一个 |
| PUT | `/policy` | 按版本保存密钥策略，必要时明确确认历史补价 |
| PUT | `/price` | 按版本保存手动价格 |
| POST | `/sync-models` | 从宿主同步模型目录 |
| POST | `/model` | 添加模型目录 ID |
| POST | `/sync-prices` | 排队执行缺失价格补全 |
| GET | `/reviews` | 指定密钥的异常待核对记录；可选 model 或 channel，均为空查询整把密钥，不能同时指定 |
| POST | `/settle` | 提交核对用量与依据 |

旧 `/settings` 和 `/usage` 路由不存在。

## 额度与持久化

SQLite 使用 WAL 和 FULL 同步。额度按准入开始时间归属自然周期；跨午夜执行仍计入原周期。通过查询周期范围汇总账本，不依赖午夜清空数据。

策略形态为 `revision / note / period / total_quota_enabled / total_access / total_quota / rule_mode / rules / channel_rules`。两套分项规则均含 `access / quota`，额度含 `unit / limit`。`total_access` 是“全部模型”范围的权限（`allow`／`deny`，缺省 `allow`）：总开关开启且为 `deny` 时，该密钥在选中凭据前后的拦截中都直接返回 403 `key_forbidden`，不要求上限，已存的 `total_quota` 保留但不参与额度计算。总开关独立于上限，权限为 `allow` 时开启却没有上限会被拒绝。旧策略缺少模式时默认 model，缺少总开关时根据旧 total_quota 是否存在推导。旧客户端 PUT 省略 `total_quota_enabled`、`total_access`、`rule_mode`、`channel_rules` 时保留已存值。旧逐模型周期统一时保留，混合周期迁移为每月，没有额度时使用每天。

```json
{
  "revision": 0,
  "note": "开发团队",
  "period": "day",
  "total_quota_enabled": true,
  "total_quota": { "unit": "money", "limit": "10" },
  "rule_mode": "channel",
  "channel_rules": {
    "gpt": { "access": "allow", "quota": { "unit": "tokens", "limit": "100000" } }
  },
  "rules": {
    "gpt-example": { "access": "allow", "quota": { "unit": "tokens", "limit": "50000" } }
  }
}
```

请求先识别密钥并读取策略。没有生效配置时立即返回成功；有配置时再校验当前模式权限，并检查已开启的总额度与当前渠道／模型额度。`usage` 每条执行只保存一次；总量按密钥与周期汇总，渠道／模型增加对应过滤条件。`usage_key_period`、`usage_channel_period` 等索引支持范围汇总。429 的 `scope` 为 `total`、`channel` 或 `model`，包含实际模型和渠道信息。

数据库 schema 2 在事务中为请求和用量回填渠道，并添加每把密钥的同步时间及索引；保留原费用、Token、ID 和时间，迁移可重入。页面提示账本可能缺少插件停用或密钥无规则旁路期间的数据。升级前备份数据，回退版本需恢复备份。

权限、额度、周期保存后作用于新请求。改变周期、额度单位或上限不会清空记录。无价格的记录保持未计价，切入金额额度前需要确认补计；未计价请求仍执行时先等待其结算。

金额额度启用时，只检查有效范围，按每条历史用量对应模型的价格预览并补计。总金额覆盖所有记录；否则选取当前模式下互不重叠的金额范围，保证重叠记录只补计一次。所有费用和策略在同一事务提交，缺价或拒绝补计不产生部分更新。新请求涉及有效金额额度时必须具有价格快照。暂停或禁止的分项规则、关闭的总额度不要求价格或补计。

启用额度或切换模式会纳入本周期此前已有的用量记录。若关闭总额度后当前模式仍有规则，获准请求继续记账；若当前模式也没有规则，则直接旁路，期间消耗不会补造。没有准入记账记录的旧请求不会被孤立回调补造。额度开关与配置切换均不删除账本。

金额和价格使用六位十进制定点数；每条执行费用向上取整到 `0.000001 USD`。输入、输出、缓存和推理按宿主归一化语义处理，避免重复计费。已准入请求保存价格快照，后续修改价格不追溯覆盖。

请求 ID 与用量执行 ID 可以不同，按宿主 TraceID、密钥、模型关联；执行通知去重，实际产生用量的重试分别记账。完成通知不代表零用量。超过等待窗口或重启发现未结算请求时进入待核对；迟到真实记录替换人工记录。

待核对只阻止涉及有效额度的范围：总额度影响整把密钥、渠道额度影响渠道、模型额度影响模型。已配置密钥中无有效限额的请求继续记录，不因历史待核对被阻止；没有生效规则的密钥直接旁路。核对接口支持三种范围；人工结算和迟到修正保留准入渠道。

本实现按已结算用量阻止后续请求。已准入的并发或流式请求可能超额，不是严格消费封顶。面向单个宿主和一份本地数据库。

## 自动补全模型价格

参考 CPA-Manager-Plus 提交 `29d676f8eebfbc11eedc96573f3a059360163a3e` 的价格服务、HTTP 接口和模型价格手册，独立实现适合本插件的基础费率同步。

来源优先级为 models.dev、LiteLLM、OpenRouter。采用明确、唯一的模型匹配，优先官方规范身份，不采用模糊名称截断。模型别名使用实际目标价格。缺少输入／输出价格、歧义和非法数值保持未设置，不能视为免费。

models.dev 价格按百万 Token 读取；LiteLLM / OpenRouter 每 Token 价格精确转换。解析科学记数法，明确零价格保留，正的极小价格不会舍入为免费。仅处理基础文本输入、输出、缓存读取和缓存写入费率。

后台线程在启动、新模型发现、默认每 6 小时和手动触发时执行。网络访问不占请求拦截锁，使用独立 SQLite 连接、连接和请求超时、响应大小限制。仅匿名获取公开目录，不发送密钥或用量。

事务中的 `INSERT OR IGNORE` 只写缺失价格，已有手动或自动价格均保留。手动编辑与自动插入使用数据库事务和版本控制解决竞争，手动保存清除自动来源标记。全部来源失败保留现有数据并记录中文错误，5 分钟后重试。

价格来源、匹配模型和同步时间存入 `price_origins`。工作线程具有取消标记和可等待退出的生命周期；配置热更新排队应用新来源配置。

## 界面与交互规范

管理页按用户提供的 MeteoAlpha `DESIGN.md` 落实通用视觉和交互规则，并参考 CPA-Manager-Plus 官方演示的浅色侧边导航、蓝灰配色和分区卡片。没有复制其业务页面或修改该规范文件。

- 统一语义颜色、字体、间距、圆角、动效和层级变量。正文 14px、辅助文字 12px、页面标题 24px，内容区最大 1440px。
- 侧栏 240px；窄屏改为顶部导航。页面边距桌面 24px、窄屏 16px。表格只在自身区域横向滚动，保留 14px 正文。
- 管理控件高 32px，权限框 88px、周期框 112px、备注和额度输入 224px、搜索框最大 240px；所有短字段不超过 300px。
- 密钥详情使用渐进式“限制设置”。默认不渲染全部渠道和模型，只显示用户已经添加的限制；没有限制时展示空状态和单一添加入口。
- 总额度使用紧凑开关。首次开启先弹出额度配置，成功后才在列表中显示“全部模型”；关闭后隐藏对应设置行，但保留上限和用量，重新开启继续沿用。
- “添加限制”统一选择全部模型、渠道或单个模型，然后只展示所选范围需要的权限、额度和目标字段。渠道与模型规则继续互斥；跨类型添加时明确提示现有规则保留但暂停。
- 已添加限制列表支持行内允许／禁止、额度编辑和移除。渠道行可按需展开成员模型；密钥已有生效规则时，未配置范围默认放行且不限额。空状态和页尾明确说明无规则密钥旁路及账本覆盖边界。
- 表格展示模型、权限、额度摘要、本周期用量、操作。额度单位和数值集中到弹窗，避免每行堆叠表单。顶部保存操作在长表格滚动时保持可见。
- 额度类型使用原生互斥单选，可用方向键切换。Token 和金额分别记住本次输入；切换单位不自动换算或复用另一单位的数值。
- 总额度、渠道与模型共用额度弹窗。总额度只选 Token／USD，分项另有不限额。展示密钥周期、范围用量及重置时间，保存一次即提交，保留其他配置。已有开关、模式、备注等草稿时明确提示一并保存。单模型缺价时禁用金额保存；总金额／渠道金额由服务端检查历史补价条件。降低上限至已用量以下时提示会立即拦截新请求。
- 数值错误在字段附近提示；操作反馈从页面顶部出现。异步按钮保持宽度、显示处理中状态并阻止重复提交。
- 弹窗锁定背景滚动，正文可以单独滚动，标题和底部操作区保留；Esc 与取消直接关闭，不使用嵌套弹窗。未保存的密钥修改不弹窗拦截：切换密钥、页面或刷新时按密钥保留页面内草稿，由“保存配置”或“放弃修改”显式处理；服务端版本号拒绝基于过期配置的保存。
- 搜索无结果与尚无数据分别说明原因和恢复操作。宿主密钥来源失败时以错误缺省状态替换密钥内容。
- 桌面密钥列表栏为 300px，1024～1200px 收窄为 264px，1024px 以下改为横向卡片列表；桌面列表栏随页面吸顶并在内部滚动。标题区统一显示“查看完整／隐藏完整”，按需读取全部有效密钥并集中切换明文；显示状态在保存、刷新和切换页面后保持，期间新增的有效密钥自动补读，已删除密钥的明文立即移除；仅在点击隐藏、断开或更换凭据、重新打开页面时清除明文。卡片只保留复制图标按钮，复制成功后短暂显示勾选。搜索始终支持完整密钥，由已鉴权服务端返回匹配标识，不要求页面先取得或显示全部明文。
- “设置”页固定展示全局请求拦截开关，切换后通过管理接口立即写入数据库并同步顶部状态。未启用时页面顶部说明所有请求会直接放行且不记账；启用后，没有生效规则的密钥仍旁路，规则可预先配置。
- 价格后台状态可以刷新；价格表内容未变化时保留 DOM，避免打断行操作。键盘焦点、减少动态效果和状态文字均保留。
